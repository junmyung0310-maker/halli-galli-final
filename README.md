
# Halli Galli - Online Ranking System

## 1. 프로젝트 소개

본 프로젝트는 1인용 할리갈리 게임에 온라인 랭킹 시스템을 추가한 프로그램이다.

기존 게임은 사용자 1명과 컴퓨터 플레이어 2명이 경쟁하는 방식으로 구성되어 있었다. 5주차 과제에서 더욱 발전되어 이번 9주차 과제에는 Supabase REST API를 활용하여 게임 결과를 서버에 저장하고 다른 플레이어의 기록도 확인할 수 있는 온라인 랭킹 시스템을 구현했다. 그 외에도 점수 시스템과 난이도를 일부 조정했다.

## 2. 게임 구성 및 주요 기능

### 2.1 게임 진행 방법

사용자는 두 명의 컴퓨터 플레이어와 할리갈리 게임을 진행한다.

- `↑` 방향키: 자신의 카드 제출
- `Enter`: 종 치기
- 같은 종류의 과일이 정확히 5개 보일 때 종을 치면 성공한다.
- 잘못 종을 치면 카드 한 장을 제출하는 페널티가 발생한다.
- 게임 종료 후 결과 화면에서 최종 점수를 확인하고 온라인 랭킹에 등록할 수 있다.

### 2.2 점수 계산 방식

단순히 게임에서 승리했는지만으로 점수가 결정되지 않도록 다음과 같은 계산 방식을 적용하였다.

| 조건 | 점수 |
|---|---:|
| 게임 종료 시 보유 카드 1장 | +100점 |
| 게임 승리 | +1,000점 |
| 정확하게 종 치기 | +150점 |
| 잘못 종 치기 | -300점 |

최종 점수는 다음과 같이 계산한다.

`최종 점수 = 카드 수 × 100 + 승리 보너스 + 정답 횟수 × 150 - 오답 횟수 × 300`

단, 최종 점수는 0점 미만이 되지 않도록 처리한다.
이 방식을 통해 같은 카드 수로 승리한 플레이어라도 종을 얼마나 정확하게 쳤는지에 따라 서로 다른 점수를 얻는다.

## 3. API 활용 및 데이터 구조

### 3.1 API 선택 이유

Supabase는 PostgreSQL 기반 데이터베이스와 REST API를 제공한다.

기존 게임은 프로그램을 종료하면 다른 플레이어와 결과를 공유할 수 없었다. 이를 개선하기 위해 Supabase를 선택하였으며, HTTP 요청을 통해 게임 결과를 저장하고 조회하도록 구현하였다.

API 설계 과정은 `api-plan.md`에 정리하였다.

## 4. 핵심 코드 구조 및 동작 원리

### 4.1 게임 클래스 구조

클래스는 별도로 수업시간에 배우지는 않았으나 의미 정도만 학습했다.
- `Card`: 과일 종류와 개수를 저장하고 카드의 표시 정보를 관리한다.
- `Player`: 플레이어 이름, 컴퓨터 여부, 카드 덱, 현재 공개된 카드를 관리한다.
- `HalliGalliGame`: tkinter 화면 생성, 턴 진행, 종 판정, 승패 결정 등 전체 게임 흐름을 제어한다.

게임의 주요 함수는 다음과 같다.

| 함수 | 역할 |
|---|---|
| start_game() | 카드 덱을 생성하고 게임 상태 초기화 |
| user_play_card() | 사용자의 카드 제출 처리 |
| execute_turn() | 현재 플레이어의 카드 제출 및 턴 진행 |
| check_five() | 공개된 카드의 과일 개수가 정확히 5개인지 검사 |
| ring_bell() | 종 치기의 성공 및 실패 판정 |
| update_board() | 카드 및 게임 상태 화면 갱신 |
| end_game() | 게임 종료, 승패 결정 및 결과 표시 |

### 4.2 과일 5개 판정

`check_five()` 함수는 공개되어 있는 카드의 같은 과일 개수를 합산한다.

### 4.3 종 치기와 점수 계산

`ring_bell()` 함수는 종을 친 시점에 과일 5개 조건이 충족되었는지 확인한다. 정확한 경우에는 성공 횟수를 증가시키고, 잘못 친 경우에는 실패 횟수를 증가시킨다. 
(self.wrong_bells += 1 ,
self.correct_bells += 1)
전 판에 이긴 사람이 다음 턴의 선 플레이어가 되는 규칙도 담당한다. 이러한 기록은 게임 종료 후 최종 점수를 계산할 때 사용된다.

### 4.4 온라인 랭킹 연동

`ranking_api.py`는 게임 로직과 API 통신을 분리하기 위해 사용한다.

- `submit_score()`: 닉네임과 점수를 서버에 등록
- `get_top_rankings()`: 점수가 높은 순서대로 랭킹 조회

게임 로직과 API 통신을 별도의 파일로 구분하면 코드의 역할이 명확해지므로, 별개의 코드로 만들어달라고 요청했다.

## 5. 설치 및 실행 방법

### 5.1 실행 환경 준비

Python과 uv가 설치된 환경에서 프로젝트 폴더를 연다.

다음 명령어로 프로젝트 의존성을 설치한다.

```bash
uv sync
```

### 5.2 환경변수 설정

프로젝트 최상위 폴더에 `.env` 파일을 생성하고 다음 내용을 입력한다.

```dotenv
SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

Supabase Dashboard에서 프로젝트 URL과 Publishable key를 확인할 수 있다.

`.env` 파일은 `.gitignore`에 등록하여 GitHub에 업로드되지 않는다.

### 5.3 게임 실행

```bash
uv run python halli_galli.py
```

### 5.4 API 연결 테스트

```bash
uv run python api_test.py
```

## 6. 프로젝트 파일 구성

```text
project/
├── halli_galli.py
├── ranking_api.py
├── api_test.py
├── api-plan.md
├── README.md
├── pyproject.toml
├── uv.lock
├── .python-version
├── .gitignore
└── .env
```

- `halli_galli.py`: 게임 실행 및 GUI 구현
- `ranking_api.py`: Supabase REST API 통신
- `api_test.py`: API 요청 테스트
- `api-plan.md`: API 설계 및 구현 계획
- `README.md`: 프로젝트 설명과 실행 방법
- `pyproject.toml`, `uv.lock`: 의존성 및 실행 환경 관리
- `.env`: API 연결 설정(Git 추적 제외)
- `.gitignore`: Git에 포함하지 않을 파일 지정

## 7. 참고 및 유의사항

- 온라인 랭킹 기능은 인터넷 연결과 Supabase 프로젝트 설정이 필요하다.
- API 연결 정보는 `.env` 파일로 관리한다.
- `.env`와 `.venv`는 Git 저장소에 포함하지 않는다.
- 프로젝트 실행 환경은 `uv`를 통해 재현할 수 있도록 구성하였다.
- API 설계 및 개발 과정은 `api-plan.md`와 AI 협업 대화 기록을 통해 확인할 수 있다.
